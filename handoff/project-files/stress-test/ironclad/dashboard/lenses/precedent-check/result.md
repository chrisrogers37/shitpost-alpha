- **[major] security**: "Public by design, rate-limited per address" rests on a limiter that does nothing today, and the plan's 5-second polling multiplies the exposure.
  - Precedent: #163 (2026-05-29) added slowapi, and its follow-up commit claimed to fix proxy IPs by switching to `get_ipaddr` (api/rate_limit.py:10). I checked the installed slowapi 0.1.10: `get_ipaddr` tests `"X_FORWARDED_FOR" in request.headers` (underscores). A real `X-Forwarded-For` header does not match (I ran it against starlette `Headers`: False for the underscore name, True for the hyphenated one), so it falls back to `request.client.host`. uvicorn starts without `--forwarded-allow-ips` (railway.json web startCommand), so behind Railway that is the proxy, and all visitors share one bucket. No test covers it (nothing under shit_tests/ exercises slowapi; the open issue #222 lists "slowapi enforcement" tests as undone). #241 (2026-08-20) then named per-IP limiting as "the abuse control" for the public API. Unverified: whether `FORWARDED_ALLOW_IPS` is set on the service. I did not read Railway variables, per the run rules.
  - Load: each open tab polls `/alerts/changes` 12 times a minute, plus `/prices/latest` 12 more on an open signal page (notes/ui-plan-hookups). The old limits were 60/min for the feed and 30/min for prices (api/routers/feed.py:14, prices.py:15). If new routes reuse those figures and the bucket is shared, about five tabs exhaust it for everyone and the "live" dot goes grey on launch day. The old client also retries failed calls twice by default (frontend/src/App.tsx:9, issue #228 L6), so a 429 would be retried into the limit.
  - The engine plan (engine.md:78) and the notification notes already say limits must key on the real client or API key. The dashboard doc says only "rate-limited per address" (source-dashboard.md:312-314), and D1, the first PR to ship `/api/v1`, has no limiter work or test.
  - **Recommendation:** Put the limiter fix in the first PR that creates `/api/v1` (D1 or engine PR 1). Key on the trusted proxy hop, not the raw header, which a client can forge unless Railway overwrites it. Pin it with a two-address test. Set per-route budgets sized for 5-second polling, and serve `/alerts/changes` with `Cache-Control: max-age=3` or an ETag so polls are cache hits shared by all viewers. Make the client stop and back off on 429 instead of retrying.

## Gaps

- **[major] architecture**: D1 promises link previews, but the stack is a static SPA served by a catch-all, and nothing in the repo does server-side meta tags.
  - Evidence: `frontend/index.html:4-8` has only charset, viewport, theme-color and a title. `api/main.py:80-95` returns the same `index.html` for every non-file path. Telegram and X crawlers do not run JavaScript. The plan says "A link pasted into Telegram or X shows a preview card" (source-dashboard.md:193) while the stack row says "served as static files" (source-dashboard.md:136-142). Growth asks for server-rendered titles and images on five page types. This is novel ground (no prior art), but the catch-all is residue that already bites agents: AGENTS.md:32 records that wrong `/api` paths return HTML with a 200 instead of a JSON 404. A public API for agents needs the opposite.
  - **Recommendation:** Name the mechanism in D1. Add a small `/s/{id}` route that reads the signal and injects title, description and og tags into the built `index.html`, with one static card image. Register a JSON 404 for `/api/{path}` before the catch-all and test both. Leave generated per-signal images for D1b, off the cutover path.

- **[minor] scope**: The "typical path of similar past posts" overlay (source-dashboard.md:186) is Historical Echoes again, and its data may not exist.
  - Precedent: echoes (#134, pgvector embeddings, 31 tests) shipped, and `frontend/src` has no consumer for it (zero hits; issue #228 L9 calls it "dead weight"). The engine plan deletes echoes (engine.md:27, 154, 175). The database keeps 1-minute bars only for alert windows and 30 days (engine.md:78), and `backtest_summary` holds one number per window (7 points), so a drawn minute-level path has no source.
  - **Recommendation:** Cut the overlay from D1 and D3. The "typical move at each window" numbers already in the Calls section (source-dashboard.md:184) carry the same message. If a picture is wanted, mark the 7 window medians on the x-axis.

- **[minor] testing**: Verification leans on Playwright and a CI job that are unproven in this setup, and the repo's own test baseline is not clean.
  - Evidence: issue #228 L5 ("no frontend test suite") has been open since 2026-07-07. #214, a Hooks-order bug, shipped for want of one. #241 verified only `api`, `notifications` and `config` directories because the full 2,035-test suite exceeds the local window, and it recorded 3 existing failures on main plus a conftest name collision. The notes' baseline is 101 passing and 1 failing api tests. The sandbox has no Chromium, Chrome or Firefox and no `~/.cache/ms-playwright`, and the mission's host allowlist does not name Playwright's download host. A single HEAD probe to cdn.playwright.dev got no response. That makes "a browser test sees a new alert within 5 s" and the phone/laptop screenshots unverified.
  - **Recommendation:** Prove a Playwright browser installs and runs in the sandbox before D1 starts. Put the load-bearing logic under Vitest component tests: the "new" bar, pause and resume of the change cursor, 429 backoff, and the empty states. Keep Playwright to one or two smoke tests. Count the CI job as dependent on engine PR 1, since the old code has no CI.

- **[minor] compatibility**: Public-API residue from #113 and #241 does not fit a public API on a new domain.
  - Evidence: CORS defaults to the old Railway URL (api/main.py:34-35), so browser clients on other origins, such as an agent playground or a third-party site, are blocked even though #241 calls the data public. HSTS is set with `includeSubDomains` for a year (api/middleware.py:15-17), which will bind every subdomain of the new domain, including analytics or docs hosts. There is no CSP (issue #222). Symbol and limit inputs on public routes were never validated (#222, M17), and the new `/bars/<symbol>` and `/evidence/<topic>/<ticker>` are the same shape.
  - **Recommendation:** Decide CORS for `/api/v1` explicitly: open to GET with no credentials, since it is public, and closed everywhere else. Drop `includeSubDomains` until every subdomain is known to serve HTTPS. Validate symbol and topic against the instrument table and bound every limit and page size.
